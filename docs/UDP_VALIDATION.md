# UDP Response Validation

This document records the supported parsing/correlation scope and the review
of unsupported variants. A received datagram establishes responsiveness, not
authenticated identity or complete discovery. Default structural checks add no
queries, multicast listeners or external scanner dependencies. Optional authenticated
UDP/161 sessions are separately documented in [SNMP sessions](SNMP_SESSIONS.md);
the table below describes the default structural response classifier, not that
credentialed client.
The optional framed UDP/11211 path below performs its own bounded exchange.
Optional SNMP discovery adds only the bounded queries documented below.
Optional UDP/137 node-status discovery replaces the generic probe with one
correlated unicast query, as described below.

## Query Matching

The scan passes the actual sent probe to the response classifier. A structurally
valid reply with mismatched fields remains a responsive port, but its service
version is cleared and identification confidence is low. Matching fields retain
medium confidence, not authenticated identity or guaranteed replay protection.
Default DNS/SNMPv1 identifiers remain fixed; the additional SNMP queries use
fresh positive 31-bit identifiers generated by Go's cryptographic random reader.

| Current Probe | Checked Fields | Limits |
| --- | --- | --- |
| DNS | Transaction ID, opcode, echoed question name/type/class | Case-insensitive name comparison; no authentication |
| SNMPv1 | Version, community, request ID, binding OIDs/count/order | Community never appears in output; tooBig may omit bindings |
| Optional SNMPv2c | Version, community, random request ID, binding OIDs/count/order | One `sysDescr.0` GET; same existing `public` community; no returned values disclosed |
| Optional SNMPv3 discovery | Random message ID, request ID when available, noAuthNoPriv USM report, discovery counter OID/type, empty user/context name, coherent engine/context IDs | A Report request ID of zero is allowed; engine identity not authenticated or disclosed |
| NTP | No reliable correlation available | Existing client packet has a zero transmit timestamp |
| SSDP | No unique transaction identifier available | Header shape only; LOCATION is never fetched |
| Optional NetBIOS NBSTAT | Random transaction ID, response opcode/type/class, wildcard answer name, complete bounded record framing | One unicast node-status query; no authentication or name/MAC disclosure |
| Default NetBIOS/mDNS/LLMNR | No valid query to correlate | Existing generic one-byte probe remains unchanged |

A v2c/v3 reply cannot match a v1 query. A schema-valid reply observed without
compatible query context remains structural evidence only.

## Optional SNMP Discovery

On UDP/161, `-Dv` (or `-De`) with service detection permits two sequential
fallbacks if the initial SNMPv1 exchange does not yield a matched protocol:

1. A SNMPv2c GET for `sysDescr.0`, using the existing `public` community only.
2. A SNMPv3 noAuthNoPriv request with empty engine/user/context fields and an
   empty binding list, following [RFC 3414 section 4](https://www.rfc-editor.org/rfc/rfc3414.html#section-4).

The initial probe and its retry policy remain unchanged. Each fallback has one
attempt, uses the global attempt limiter and existing UDP timeout, and stops
after a matched identification or connection refusal. No fallbacks run with
`-g`, on other ports, or without service detection. The worst case adds two
timeout intervals, not an unbounded walk. A prior responsive observation is
retained if later queries fail. If identifier generation fails, no additional
queries are sent.

Discovery accepts only the existing bounded plaintext Report subset with an
`usmStatsUnknownEngineIDs.0` Counter32 binding. The message ID must match; a
nonzero request ID must also match. A zero Report request ID is allowed when
unavailable, as specified in [RFC 3412 section 7.1](https://www.rfc-editor.org/rfc/rfc3412.html#section-7.1).
Engine and context-engine IDs must agree, and user/context name must be empty.
Reports using empty/different context-engine IDs or other security/error
variants remain unconfirmed by this matcher. No engine
follow-up, authenticated exchange, product-version extraction, community
enumeration, SET, walk or reassembly is implemented by this discovery fallback.
Credentialed SNMPv3 uses the separate session path documented above. Response metadata
never includes communities, engine identifiers, users or binding values.

## NetBIOS Node Status Query

On UDP/137, `-u -Dv` (also implied by `-De`) sends one read-only, unscoped
wildcard NBSTAT query instead of the generic probe. The 16-bit transaction ID
comes from Go's cryptographic random reader; entropy failure sends nothing.
There are no automatic query retries, broadcasts, redirects, registrations or
name releases. Default, disabled-detection and `-g` scans remain unchanged.
The existing global attempt limiter and configured UDP timeout apply.

An identification requires a matching ID, wildcard answer name, NBSTAT type,
IN class and the existing bounded record validator. Mismatched or malformed
responses retain responsiveness without a confirmed protocol/version claim.
Matching remains medium confidence: NetBIOS has no authentication here.
Names, workgroups, statistics and MAC addresses are never copied into metadata.

Deterministic query/correlation and policy tests cover malformed and truncated
packets, mismatched IDs/names/types, entropy failure, disabled/controlled modes
and the single-attempt bound. A dedicated fuzz target checks input ownership
and correlation invariants. On October 16, 2026, an authorized Metasploitable3
Windows VM returned a correlated node-status response; the Linux VM timed out
and correctly remained `open|filtered`. This does not certify every NBNS variant.
The query follows [RFC 1002 section 4.2.17](https://www.rfc-editor.org/rfc/rfc1002.html#section-4.2.17).

## Memcached Query And Reassembly

`-u -Dv`/`-De` on UDP/11211 sends one framed stats request with a fresh 16-bit
identifier. A connected socket restricts the peer; matching headers contribute
to a session-local assembly. This is correlation, not authentication. Default
and controlled-profile scans keep their existing behavior.

The implementation bounds datagrams to 2048 bytes, assemblies to 16 fragments
and 16 KiB, and processing to 32 reads. One fixed deadline covers the response,
capped at five seconds; fragments and duplicates never renew it. Sequence slots
may arrive out of order; identical duplicates do not consume additional payload
memory. Conflicting duplicates, inconsistent totals, invalid reserved fields and
oversize/expired messages abort identification. Unknown request IDs contribute
no payload. The state exists only for one query and is discarded afterward.

Complete stats framing is required. Returned values are excluded from metadata;
only a bounded, validated version field may identify the product version.
Evidence includes actual fragment/byte counts. Missing or malformed fragments
do not erase an observed responsive port or invent a product identification.
No SET, flush, cache-key enumeration or item retrieval is implemented.

On October 16, 2026, an isolated Memcached 1.6.45 container returned two fragments
and 2238 payload bytes. The opt-in CLI test verified the reassembled version and
confirmed that the default path remained unconfirmed. See CONTRIBUTING.md for
reproduction; record the image digest when comparing later runs. This validates
Memcached application fragments, not generic IP or NetBIOS datagram reassembly.
The wire format follows the [upstream protocol](https://github.com/memcached/memcached/blob/master/doc/protocol.txt).

## Variant Review

| Variant | Policy | Reason |
| --- | --- | --- |
| SNMP definite BER with non-minimal lengths | Supported with bounded normalization | Framing normalized; standard ASN.1 decoding still validates values |
| SNMP indefinite lengths / constructed simple values | Rejected | Prohibited by the SNMP BER restrictions |
| BER high-tag-number forms, length fields over four octets, nesting over 16 levels | Low-confidence fallback | Outside the bounded implemented subset |
| SNMPv1/v2c Response-PDU | Structural validation; query fields checked when a compatible query exists | Not authenticated identity |
| SNMPv3 plaintext USM noAuthNoPriv Response/Report, zero flags | Structural validation; optional discovery Report subset is correlated | Explicitly unauthenticated; no general v3 session |
| SNMPv3 authNoPriv/authPriv in standalone structural parsing | Low-confidence fallback | Authentication/decryption require the separate `--snmp-config` session; supported algorithms and limits are documented in SNMP_SESSIONS.md |
| Other SNMP security models/ciphers | Unsupported | The optional client supports USM SHA-256/SHA-512 and optional AES-128, not every SNMP security variant |
| Traps, informs, other SNMP PDUs | Low-confidence fallback | Not replies to the existing query |
| NetBIOS NB/NBSTAT positive replies | Bounded structural validation; optional NBSTAT queries correlated | Default generic probe is unchanged; deep-mode wildcard status responses must match the actual sent query |
| NetBIOS negative name-query replies, codes 1/2/3/5 | Bounded structural validation, medium confidence | Encoded name and empty NULL record required; no query correlation or server identity |
| NetBIOS redirects with encoded NS target and matching A owner | Bounded structural validation, medium confidence | Exact decoded-name match, RFC flags/counts and IN class; never followed, targets not disclosed, no query correlation |
| Other NetBIOS errors/redirect forms, WACK, registration/release replies | Low-confidence fallback | Outside the implemented name-query/status/redirect response subset |
| UDP/138 datagrams, fragmented NetBIOS messages | Low-confidence fallback | No datagram decoder or reassembly is implemented |

Existing single-datagram validators use the 2048-byte bound. A fallback never
promotes raw response values, usernames, engine identifiers, communities,
hostnames, workgroups or MAC addresses into identification metadata. Redirects
are not followed. Completing this review does **not** mean every variant is
implemented; other authenticated security workflows, protocol-specific queries
and application-level reassembly schemes require separately scoped changes.

## Deterministic Validation

Unit fixtures cover matching and mismatched IDs, questions, communities and
OIDs; BER normalization and depth/length limits; unsupported security models;
NetBIOS response variants; disabled detection; and disclosure prevention.
Negative NBNS fixtures cover both the zero-answer-counter layout shown with a
NULL record in RFC 1002 section 4.2.14 and a count-one layout. Validation uses
a private counter-normalized copy only for the zero-counter form and rejects
header-only errors, incorrect flags/classes/TTL, unsupported codes, truncated
records and trailing data. Input bytes are unchanged. Errors describe the
name-service reply, not a closed port, vendor version or authenticated host.
Dedicated fuzz targets exercise query matching and BER framing. Tests use no
live targets or private captures. Run `make ci` before merging.

Generic UDP reads retain one overflow byte, so a datagram exceeding the
2048-byte parsing limit cannot be identified from a silently truncated prefix.
Loopback regressions cover matching, wrong-ID, truncated and oversized NBSTAT
responses; malformed payloads do not erase the observation of responsiveness.

SNMP discovery fixtures also cover query encoding, entropy failures, mismatched
reports, truncation, opt-in/controlled-profile behavior, retry/fallback bounds,
and preservation of responsive observations. These are simulated exchanges,
not interoperability certification against a live SNMP agent.

## Combined Validation

The October 16, 2026 integration combines optional authenticated SNMP sessions,
SNMP variant discovery, NBSTAT queries and Memcached reassembly. Local
`make ci` passes with 62.0% total coverage; NBSTAT query/correlation cases also
pass ten repeated runs and approximately 46,000 fuzz executions. A Windows
amd64 cross-build succeeds. `govulncheck ./...` reports no known vulnerabilities
for the Go 1.26.9 dependency baseline; these checks do not guarantee bug-free
code or support for unimplemented protocol variants.

The combined opt-in Net-SNMP and Memcached agent suites pass using disconnected
containers. Correct and incorrect credentials exercise SHA-256/SHA-512 with
no privacy or AES-128; Memcached returns and successfully reassembles two
datagrams. See CONTRIBUTING.md for the opt-in commands. No temporary agent
containers are retained, and no VM configuration or host NIC changes are
needed for these checks. Integration remains subject to protected-branch PR
review and checks before it reaches `dev` or a release.
